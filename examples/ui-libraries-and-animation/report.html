highf-01impact high · effort moderate · ▲4.5
Adopt shadcn/ui as your base component system — its CLI copies modern, accessible components (Radix + Tailwind) into your repo so you own and freely restyle the code, instead of fighting a black-box npm design system.
◦ shadcn/ui — README (GitHub) — source · “A set of beautifully designed components that you can customize, extend, and build on. Start here then make it your own.”
# your Next.js app $ npx shadcn@latest init && npx shadcn@latest add button card dialog input # Works with Tailwind v3. Components land in components/ui and are yours to restyle.

◦ Radix Primitives — README (GitHub) — source · “Radix Primitives is a low-level UI component library with a focus on accessibility, customization and developer experien”
# your Next.js app $ npm i radix-ui # shadcn/ui already sits on Radix; adding Radix directly is for primitives shadcn doesn't cover.
highf-03impact med · effort trivial · ▲6.0

highf-07impact high · effort moderate · ▲4.5
Adopt Motion (formerly Framer Motion) as your default for React micro-motion — declarative entrances, hover/tap gestures, and layout transitions. It's TypeScript-native and GPU-accelerated, so it fits your Next 15 + TS UI cleanly.
◦ Motion — animation library for JS, React and Vue — source · “Power of JavaScript combined with native browser APIs for 120fps, GPU-accelerated animations.”
# your React components $ npm i motion # import { motion } from "motion/react"; then <motion.div animate={{ x: 100 }} />. Pair with f-11/f-12 for tasteful defaults.
highf-08impact high · effort moderate · ▲4.5
For page/route feel, enable View Transitions in Next.js and wrap shared elements (a grid thumbnail that becomes a hero) in <ViewTransition> with a matching name — the browser animates route changes automatically, and unsupported browsers just navigate normally.
◦ Designing view transitions — source · “You name the elements that should persist, and the browser animates between their old and new positions.”
# next.config.ts $ experimental: { viewTransition: true } # Then wrap shared elements in <ViewTransition name="...">. Progressive: no-support = normal nav.

◦ Scroll-driven animation timelines — source · “Any time you rely on the main thread to render effects with JavaScript, you run the risk of blocking the main thread, wh”
# CSS $ animation-timeline: view(); animation-range: entry 0% cover 40%; # Pair with f-10 feature-detection for Firefox fallback.
moderatef-15impact med · effort moderate · ▲2.0
Replace flat single box-shadows with a multi-layer shadow — several stacked shadow lines sharing one shadow-color and graduated opacity — and store them as reusable tokens (shadow-1…6) so elevation reads as deliberate depth, not a default drop shadow.

highf-11impact high · effort trivial · ▲9.0
Always wrap non-essential motion in @media (prefers-reduced-motion: reduce) and tone it down — swap scaling/sliding for a gentle opacity dissolve, or drop durations to 0. Large scaling/panning can physically trigger discomfort, so this is a baseline accessibility must.
◦ prefers-reduced-motion — MDN — source · “Animations such as scaling or panning large objects can be vestibular motion triggers.”
# → project CLAUDE.md + - All non-essential motion must be wrapped in `@media (prefers-reduced-motion: reduce)` + (reduce to an opacity fade or 0ms). Never ship scaling/panning motion without it.

◦ Designing view transitions — source · “Old content should leave quickly so it does not compete for attention. New content should arrive more gently so the user”
# → project CLAUDE.md + - Motion defaults: travel ≤ ~60px; enters 200–400ms, exits ~150ms (exits faster than enters). + Prefer opacity+small-translate over scale. If it feels 'busy', it's too much.

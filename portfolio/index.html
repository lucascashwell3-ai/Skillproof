How it works

You’re the brain. Retrieval is off-the-shelf.

Sub-agents fetch and distill each source in isolation, so raw transcripts never touch your main context. Only compact, sourced findings come back.

01

Search plan

Loose prompt → 3–5 targeted queries per source. Printed so you can tweak it.

02

Discovery

Sub-agents return candidate videos & articles — lists only, no content yet.

03

Fetch · distill

One sub-agent per source. Raw text stays inside it; ~300-token findings return.

04

Synthesis

Merge, corroborate, classify, rank — in a clean main context.

05

Approve

Diffs proposed. Dry-run by default; --apply writes on your yes.

30–50×

A 15-source run would dump ~150k tokens of raw transcripts into your context. Sub-agent isolation collapses that to a few thousand tokens of distilled findings.

You still pay to read the ore somewhere — the win is a clean context and parallel wall-clock. Source counts are capped so cost stays bounded.
Why it’s trustworthy

Three guarantees, load-bearing.

⛏

Sourced or it’s dropped

Every finding carries a resolving URL, a verbatim evidence quote, and a timestamp for video. Anything it can’t locate a source for is discarded, never guessed. No fabricated attributions — ever.

⚖

Confidence-graded

Each claim is graded high · moderate · low against the source. The same claim from two independent sources earns a bump. low findings surface but are never auto-applied.

✦

Your context stays clean

Raw transcripts live and die inside the fetch sub-agents. Your main thread only ever holds the synthesis — that’s the whole point, and it’s what keeps quality high across many sources.

Stated plainly

Two honest caveats.

Honesty is a feature. These are in the README, not the fine print.

The cloud can’t read YouTube

local (free, no key) works from your laptop, but YouTube blocks datacenter IPs fast. So: personal use → local; cloud / CI / routine runs → hosted (Supadata or youtube-transcript.io, server-side). Goldproof detects a block and skips — it never fabricates a transcript.

X costs money per read

Uses a third-party read API, never the official X API. off by default; needs --include-x + a key; every run is bounded by a hard read cap (default 200 ≈ $0.03). No key → skipped silently.

The methodology is the product

A Skillproof grade is the result of actually installing and testing a skill against the fixed protocol below — not a popularity score, not a README impression. Every grade links to a filled worksheet: the receipts. If we didn't run it, we don't grade it. There are no placeholder grades.

Conflict of interest: we do not grade our own skills. Skillproof-family tools, if ever listed, are tagged house — not graded.

Five dimensions · 0–4 each · effectiveness ×2 · total /24

1. Triggering (×1) — fires when it should, quiet when it shouldn't

Install into a clean fixture project, then run 5 headless probes in fresh sessions: 3 natural prompts that SHOULD activate it, 2 adjacent near-misses that should NOT. A should-fire probe counts only if the harness actually invokes the skill.

Opt-in skills (disable-model-invocation: true) are scored against their own declared design: should-fire probes test explicit /name invocation; near-misses confirm it stays quiet uninvoked. A skill is graded against the activation model it promises, not one we impose.

2. Does what it claims (×2) — the heart of the grade

We run the skill's primary claimed job once — the headline use case its own README sells — and compare output against its own claims, usually against a control run without the skill.

4. Maintenance (×1) — objective recency

Last meaningful commit: <3 months = 4 · <6 = 3 · <12 = 2 · older = 1 · dead = 0. Deductions (floor 0): −1 for issues ignored >60 days; −1 for hardcoded dead models/APIs.

5. Safety (×1) — every line gets read

Before anything executes, every line of the skill's source is read — SKILL.md, scripts, manifests, hooks. Start at 4, deduct: −1 undisclosed network calls · −1 ungated writes outside the project · −1 remote-exec patterns even if disclosed · −1 credential/env reads without need.

Auto-F override: undisclosed exfiltration, credential harvesting, destructive defaults, or deliberately obfuscated code = F overall regardless of other scores, delisted with the reason published.

Grades are derived from the dimension scores by this table, never hand-set — an automated honesty gate (scripts/validate_index.py) recomputes every grade and fails the build on any mismatch.

Freshness & disputes

  • Grades older than 90 days are flagged stale — re-verify pending on the site.
  • Re-grading a newer version supersedes the old worksheet — append-only, history never edited.
  • Authors who dispute a grade can open an issue; we re-run the protocol and publish the re-test either way.

Protocol notes (v1.0)

  • Probe model pinned to a mainstream daily-driver tier (Claude Sonnet class), fresh headless session per probe.
  • Test environment: disposable Linux container, clean fixture project per skill; mutating probes get isolated fixtures.
  • Safety read-through happens before anything executes; third-party skills run only inside the sandbox.
  • Every score carries a one-line "why" — in the worksheet and in the site data. A number without a reason doesn't ship.
  • Protocol mistakes (a contaminated fixture, a failed run) are re-run and recorded in the worksheet, not papered over.
